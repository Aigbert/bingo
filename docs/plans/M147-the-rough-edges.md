# M147 — The rough edges

## Goal

[tui-identity-2026-10.md](../design/tui-identity-2026-10.md) §2, R1–R10:
ten defects a live drive found, each against `docs/design/tui.md` as
written. No change of taste and no new dependency. Most fixes live with
the producer (tool-fs, tool-bash, core, permissions, the command specs),
because after M123 the TUI names no tool and no plugin.

## Bricks, in build order

1. **Failing tests first**, one per defect, in the crate that owns it:
   - tool-fs: `Glob` and `Grep` give a `display` whose paths are relative
     inside `cx.cwd` (`~` for home outside it); the model's text is
     unchanged and still absolute (R1).
   - tool-bash: a clean call's display holds the output alone; a non-zero
     one ends with `exit N`; a killed one ends with what stopped it; the
     model's text keeps `$ <command>` and `[Exited with code N]` (R2).
   - tool-bash: `preview()` is `Preview::Command { command, cwd,
     description }` (R4).
   - sdk: a `Preview::Command` without `description` reads unchanged from
     today's fixture; one with it round-trips (R4).
   - core: `/status` groups digits: `13,812 of 191,808 tokens (7 %) ·
     compacts at 172,627`, and `tokens  54,811 in · 139 out` (R7).
   - TUI: one `count(n)` gives `812`, `1.2k`, `13k`, `1.2M` (R5); the
     paths test `/var/folders/x/T/tmp.a/cwd` elides to `/var/…/tmp.a/cwd`,
     keeping the root segment (R9).
2. **Results the person reads** (R1, R2). tool-fs `glob.rs` and `grep.rs`
   set `display: View::Text` of the relative lines. tool-bash
   `output.rs` sets `display` beside `shape`'s model text, by the rule
   `transcript/ran.rs` already draws a person's `!` line by. In the TUI,
   a `View::Text` drawn as a tool's result wears `dim`, as the plain text
   it stands for does (tui.md §4, *result*); list the snapshots this
   moves.
3. **The receipt says only what is news** (R3). `transcript.rs`
   `receipt()` draws nothing for a person's plain allow; `allowed for this
   session` and `denied — <feedback>` stay. The item is unchanged; this is
   drawing only. tui.md §4 *receipt* gets the dated rule.
4. **The card asks a sentence** (R4). sdk `event/interaction.rs` `Preview::Command` gains
   `description: Option<String>` (serde default, skipped when `None`;
   schema regenerated by its generator). tool-bash implements `preview()`
   with the input's `description`. `dialog.rs` `question()`: a command
   preview asks `Do you want to run this command?` with the command on
   its tint and the description dim above it; a url preview asks `Do you
   want to fetch this page?`; a diff keeps the summary sentence; with no
   preview the sentence is `Do you want to allow <Tool> <target>?` —
   `opening()`'s lowercasing goes, so a tool's name is never made a verb.
5. **One count** (R5, R10). `count()` in the TUI's formatting module
   replaces `activity::spent`, `tree.rs`'s and `status.rs`'s own. A child
   row and a list row say what the session wrote, `↓ 8.1k`, as the
   activity row does (`usage.output_tokens`), never input re-counted per
   request; the status line keeps the window, `13k/191k`. tui.md §4
   *child row* and *the list* get the dated rule.
6. **The drawing notice** (R6). `run.rs` `slow_draw`: no notice in a
   debug build, where it is expected; in a release build it is `Info`
   (dim), once a run. Its words lose "a debug build".
7. **Commands describe themselves** (R8). `CommandSpec.hint` is the one
   line a person reads in the `/` menu: every spec whose hint is a
   synopsis (`core/commands/mod.rs` `spec`, `bingo-permissions`
   `command.rs`, `bingo-tool-bash` `shell.rs`) gets a description, and
   free-text synopses move to `args` (`ArgSpec::Free { hint }`); existing
   `Words`/`Catalog` completion remains typed (M100). `/quit` becomes an alias of `/exit`
   (`commands.rs`). The `?` sheet (`view.rs`, `keys.rs`) draws the keys
   alone, grouped *write · move · turn · sessions*, closed by one dim row
   `/ for commands · ! for a shell line`; no binding text is clipped at
   100 columns (shorten the words, never the meaning).
8. **The root segment** (R9). `paths.rs` `elide` keeps the first segment
   of an absolute path.
9. **Records.** tui.md §10 gets one dated entry naming R1–R10;
   tui-identity §2 ticks them.

## Non-goals

- A session-wide answer for a compound shell command: `scope::narrowest`
  stays fail-closed (`split::is_simple`).
- Inline code's backticks (M73's choice), the fence's language row
  (M149), the welcome's words (M149), the rail and the panel sheet (M148).
- `--print` and channels: they draw the model text and keep it.

## Risks

- R2 changes what a person sees of every `Bash` call. The model text is
  pinned by `bingo-tool-bash` `lib.rs` tests and must not move.
- The dim rule for a `View::Text` result touches plugin displays too
  (demo-ui, jobs). That is tui.md's rule already; list the snapshots.
- Re-verify at start: the M123 rule 4f, the `Row`/`caption` shape after
  M123, `spent`'s callers, and the specs whose hint is a synopsis.
